# 楼道占用巡查处置系统

物业巡查登记公共楼道被占用物品（位置、照片、消防风险级别），向相关楼层住户
发限期清理通知；到期未清的物品由两名员工双人清点封存并开放认领，期满由主管
批准处置。纯 Python 标准库 + SQLite，零依赖。

## 一键启动

```bash
./run.sh            # 首次运行自动初始化、播种（含错认样例）并启动
# 或指定端口： ./run.sh 8080
```

打开 http://127.0.0.1:8000

- `/` 楼栋巡查总览（易燃/高风险项排最前）
- `/floor?n=3` 楼层平面示意，圆点标出占用点位
- `/item?id=3` 事件页：时间线按 **通知 → 复查 → 封存** 排列，可执行各环节操作
- `/public` 住户公告端：只展示可公开照片，不含任何住户信息，认领须描述**非公开特征**
- `/messages` 模拟消息适配器发件箱（限期通知 / 匿名公告 / 认领结果）

重置演示数据：删除 `data/hallway.db` 后再次 `python3 -m app.seed`。

## 流程与分支

登记 → 限期通知（有主发私信 / 无主发匿名公告）→ 到期复查
→ 住户自清结案 **或** 双人封存 → 认领（特征核验）→ 期满主管处置。

专项分支均独立处理：主人不明（匿名公告）、邻居误认（特征不符驳回并留痕）、
易燃物紧急移除（不等到期）、住户已自清、照片不清（重拍合格前禁止封存）、
封存后损坏登记、自清与封存并发（SQLite `BEGIN IMMEDIATE` 写锁，先到先得，
不重复封存）。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：公告隐私（无房号/姓名/手机号、守卫直接拦截泄露内容）、
自清与封存并发恰好一方成功、封存必须两名不同员工双签、
到期处置须主管角色且认领期未满不得处置。

## 数据

- SQLite：`data/hallway.db`（物品/照片/事件/通知/封存双签/认领/损坏/处置/消息箱）
- 图片：`data/photos/`（本地 SVG 现场照片，`public` 标记决定能否在住户端展示）
